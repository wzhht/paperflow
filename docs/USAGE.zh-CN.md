# PaperFlow V3 操作手册

[English](USAGE.en.md) · [返回首页](../README.md)

## 先弄清两个入口

项目根目录只需使用两个入口：

| 入口 | 什么时候用 |
|---|---|
| `一键安装.cmd` | 首次安装、更新程序依赖、选择中文或English |
| `一键批量整理Markdown.cmd` | 输入一批DOI，获取全文并集中整理Markdown |

补PDF的入口由程序生成在每批资料内，不放在项目根目录。安装和日常转换均不需要本地GPU，不安装本地MinerU。

## 1. 首次安装

1. 完整解压源码包，不要在ZIP预览窗口内双击文件。
2. 确认进入的目录直接包含 `pyproject.toml`、`src`、`scripts` 和两个CMD。
3. 双击 `一键安装.cmd`，按 `1` 选中文，或按 `2` 选English。
4. 若提示找不到Python 3.10，先按窗口链接安装完整的Python 3.10 Windows 64位版本，保留pip、Python Launcher并勾选添加PATH；重新打开安装入口。
5. 安装器会创建本目录的 `.venv`，已有可用环境则复用，然后联网安装依赖。等待显示安装完成和 `PaperFlow 0.3.0`。
6. 任意阶段报错时，查看上方错误。窗口会停留；不要把“按任意键继续”当成安装成功。

当前仅验收Python `>=3.10,<3.11`。不要复制另一个目录的 `.venv`。Python 3.10已结束维护；更高版本需另行兼容验收。安装器不自动下载或运行Python安装程序，也不需要管理员权限。

已有 `.env`、论文、报告不会被安装器覆盖或删除。失效的已有环境不会自动删除。手动安装命令见 [README](../README.md)。

## 2. 配置API

安装成功后，用记事本打开项目根目录 `.env`。安装器仅在该文件不存在时从 `.env.example` 创建它。

按自己的需要填写，**不用把所有API都申请齐**：

| 使用方式 | 需要什么 |
|---|---|
| Elsevier全文XML | `ELSEVIER_API_KEY`，并具有对应全文授权；可能需使用学校校园网出口 |
| 任意需要PDF解析的路线，包括自行下载的PDF | `MINERU_BACKEND=api` 和 `MINERU_API_TOKEN`；旧字段 `MINERU_API` / `MINERU_API_KEY` 也兼容 |
| Springer Nature OA XML | 对应 `SPRINGER_OA_API_KEY`；该key不提供订阅全文权限 |
| 其他元数据、公开全文定位或Wiley TDM | 按README配置表选填，不因填写key而获得额外订阅权限 |

示意配置如下，右侧请填写自己的值，不要照抄占位文字：

```ini
ELSEVIER_API_KEY=your_own_elsevier_key
MINERU_BACKEND=api
MINERU_API_TOKEN=your_own_mineru_token
MINERU_API_MODEL=vlm
MINERU_API_TIMEOUT=600
```

PDF会上传到MinerU服务并可能消耗账户额度；XML原生转换不调用MinerU。API失败会报错，不自动切回本地模型或轻量API。旧配置的 `MINERU_EXECUTABLE` 和 `MINERU_TIER` 已不使用。

`.env` 只保存在自己电脑，不上传GitHub，不截图发送密钥。系统环境变量同样受支持，已设置的系统值可能优先于 `.env`；改完配置后重新打开处理窗口。

## 3. 批量处理DOI

新建一个TXT清单，每行一个DOI，例如：

```text
10.1016/j.jobe.2024.110286
10.1007/s12273-025-1335-6
10.1016/j.buildenv.2025.114072
```

这些是格式示例，并不保证在所有账号、网络下均能获取全文。

1. 双击 `一键批量整理Markdown.cmd`。
2. 将TXT拖入窗口，按回车；也可将TXT拖到该CMD图标上。
3. 输入本批资料的保存位置，或回车使用窗口显示的默认目录。
4. 等待逐篇结果。不要在处理中关闭窗口或移动项目。
5. 结束后先看逐篇状态和汇总，再打开“整理好的Markdown”。

正文MD按文章标题命名，同名自动区分；默认不把摘要当全文导出。不保证100篇DOI都能产生100篇全文，实际数量取决于全文获取和转换结果。

语言在安装时选择。临时切换可在项目目录CMD中执行：

```bat
一键批量整理Markdown.cmd --language en
一键批量整理Markdown.cmd --language zh
```

第三方安装/解析日志保持原始语言，论文不会被翻译。

## 4. 文献、Markdown和记录放在哪里

保存目录在运行窗口中显示。默认位置是项目内 `workspace\批量文献\清单文件名`，每批结构类似：

```text
本批资料/
├─ 整理好的Markdown/
│  ├─ 论文标题A.md
│  ├─ 论文标题B.md
│  └─ export_manifest.csv
└─ 原始资料/
   ├─ batch_results.csv
   ├─ 补齐PDF后批量转换.cmd
   ├─ 批量补PDF转换配置.json
   ├─ 待补PDF说明.txt                 有失败或仅摘要条目时生成
   ├─ 补PDF批量结果.csv              实际运行批量补PDF后生成
   ├─ 10.1016_某篇论文DOI/
   │  ├─ paper_llm.md                原始目录中的正文Markdown，转换成功后生成
   │  ├─ qa.json                     本篇检查结果
   │  └─ PDF、XML等原始资料           视实际获取路线而定
   └─ 10.1007_某篇待补论文DOI/
      ├─ 补好PDF后双击转换.cmd
      ├─ 补PDF转换配置.json
      └─ 下载的论文原文件名.pdf        由你放入；不用改名
```

| 文件或目录 | 怎么使用 |
|---|---|
| 整理好的Markdown | 日常集中阅读，文件名是论文标题 |
| 原始资料中的论文目录 | 放补充的正文PDF；保留来源和检查记录，用于追溯或重试 |
| `batch_results.csv` | 最初DOI批次的结果；补PDF后不会自动重写这份历史批次记录 |
| `补PDF批量结果.csv` | 最近一次批量补PDF的结果；再运行会更新它 |
| `export_manifest.csv` | 阅读副本、原始MD、DOI和文件校验信息之间的对应关系 |
| `qa.json` | 判断本篇成功、警告及完整性问题的详细依据 |
| 两种“转换配置.json” | 供双击入口读取DOI和路径，不含API key；保留在原位 |

阅读目录和原始目录需要分开。无需为了看MD删除原始目录；删除原始资料会失去重试和溯源依据。自行修改过的阅读副本会受到导出保护，程序可能生成另一个副本，而不是覆盖你的修改。

## 5. 下不了全文：补一篇PDF

1. 查看窗口或“原始资料”里的 `待补PDF说明.txt`，找到对应DOI的论文目录。
2. 自行取得这篇论文的**正文PDF**，保留下载时的原文件名，放进该论文目录。
3. 每个论文目录只留一份待解析正文；补充材料、其他论文、重复版本放到别处。
4. 双击该目录内 `补好PDF后双击转换.cmd`。
5. 等待API转换，查看Status和QA。通过正文检查后，同一“整理好的Markdown”目录会补进这篇文章。

文件名可包含中文、空格或大写 `.PDF`，无需改为 `paper.pdf`。程序只查看论文目录直接包含的PDF，不递归扫描子目录，不会仅凭下载文件名猜测它属于哪篇论文。

**PDF已经下载，只是解析/API失败时，不必重新下载。** 先排除网络、额度、token或PDF问题，再重试。单篇入口是显式重试，已经完成的论文再次运行可能重复消耗额度。

## 6. 一次补四五篇或更多PDF

1. 将每篇PDF保留原名，分别放进说明中对应的论文目录。
2. 回到本批“原始资料”目录。
3. **只双击一次 `补齐PDF后批量转换.cmd`。**
4. 等待逐篇结果，查看终端汇总与 `补PDF批量结果.csv`。

批量入口会：

- 顺序处理已经放好的待补PDF，使用完整MinerU API。
- 跳过没有PDF的论文，下一次补齐后仍可运行同一个入口。
- 跳过已有成功正文，以及已生成完整正文但仍带核验警告的论文，避免重复消耗额度；警告仍需人工核查。
- 同一论文目录有多个PDF时提示，避免误选；这篇的异常不影响后续条目。
- 在本批原来的阅读目录汇总MD。

只处理已有待补配置的论文目录，不是任意PDF文件夹扫描器。直接把不同论文PDF都放在“原始资料”顶层，程序无法知道对应DOI，因此不会把它们随意配对。只需补PDF时使用此入口，不必把整个DOI批次重新跑一遍。

## 7. 只有PDF，没有DOI

已有DOI清单中的待补论文按上面操作。完全独立的本地PDF，可使用现有入口：

```bat
.venv\Scripts\paperflow.exe parse-pdf "D:\papers\article.pdf" --output-root "D:\papers\sources" --markdown-dir "D:\papers\reading"
```

该命令使用MinerU API，不会编造DOI。当前友好批量入口以DOI清单为起点；任意一堆无DOI PDF的自动配对、独立一键批处理不是本版功能。

## 8. 怎样理解成功、警告和失败

| 显示 | 含义与操作 |
|---|---|
| `success` | 通过本次路线的检查，可阅读；重要科学内容仍建议回看原文 |
| `warning` + 仅摘要/元数据 | 没有完整正文，不能作为全文使用；需要补PDF |
| `warning` + 已生成正文 | 可能是可信页数缺失、版本待核验或其他质量警告，查看 `qa.json`；不要直接认为完全验收通过 |
| `FAILED` | 本篇未完成；查看错误。缺全文就补PDF，API/解析失败则先处理对应原因 |
| “按任意键继续”或批次结束 | 只代表窗口等待或批次跑完，不代表每篇成功 |

获取到文件、确认论文身份、核验完整性和转换MD是不同环节。作者稿/预印本与出版版需要区分，摘要不会冒充全文。历史代表样本验收见 [VALIDATION.md](VALIDATION.md)，不代表全出版社可用或新的批次自动通过。

## 9. 常见问题

| 问题 | 怎么处理 |
|---|---|
| 找不到环境或PaperFlow依赖 | 从项目根目录运行安装入口；不要只复制CMD文件，也不要复制旧 `.venv` |
| `pip install` 失败 | 查看最先出现的网络、下载或依赖报错；解决后重新安装；安装器不会自动更改网络或代理 |
| 401/403、摘要、购买提示 | 检查授权、网络和对应API；有些论文需要校园网，有些仍无法获取，按提示自行补PDF |
| MinerU token/额度/超时错误 | 检查 `.env`、账户额度及网络；必要时调整 `MINERU_API_TIMEOUT`；保留PDF后重试 |
| QA中出现 `local_pdf_mineru` | 这是本地PDF输入的来源标签，不代表本地模型；实际解析方式看 `mineru.backend`，应为 `api` |
| 旧日志出现本地llama-cpp/GPU退出码 | 当前配置应为 `MINERU_BACKEND=api`；旧 `local` 配置会提示迁移，不再调用本地模型 |
| 同一目录有多个PDF | 移出补充材料或重复版本，仅保留正确的正文，不用改名 |
| 补PDF成功，但 `batch_results.csv` 仍写失败 | 它是原始批次历史；查看本次补PDF清单及最新 `qa.json` |
| 移动项目后入口失效 | 虚拟环境及生成的入口记录路径。更新代码不要求移动目录；确需迁移时在新位置安装，并重新生成受影响的补PDF入口 |
| 想把现有MD集中导出 | 使用 `export-markdown`，不会重新获取或调用MinerU，命令见README |

## 10. 更新、保存和发布

更新程序前保留自己的 `.env` 和 `workspace`。源码包不包含这两者，也不包含虚拟环境；GitHub代码备份不是文献备份。已有数据继续保留在本机，不随发布上传。

本程序只负责文献获取和转换，不自动同步ResearchFlow索引。GitHub发布操作见 [发布指南](PUBLISH.zh-CN.md)。
